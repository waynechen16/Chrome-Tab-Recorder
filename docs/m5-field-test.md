# M5 實戰驗證手冊

對應 implementation plan 第 10 節的 M5：用一堂真實的線上課程完整跑一次，收集問題後修正。驗收條件是完整錄下 2 小時以上的課程，影音同步、可拖曳，CPU 佔用可接受。

需要的時間：課前約 10 分鐘準備，課後約 10 分鐘檢查與回報。

## 一、課前（上課前一天或開課前 15 分鐘）

1. **更新 extension。** 到 `chrome://extensions`，在 Tab Recorder 上按重新整理圖示，確認版本是 0.5.0 以上（設定頁最下方會顯示版本）。
2. **執行課前檢查。** 點工具列的 Tab Recorder → 下方「設定」，頁面最上方的「課前檢查」會自動執行一次。
   - 全部是 ✓ 或 i：可以直接上課。
   - 有 !：依說明處理，例如 CPU 核心少就改 VP8 或 720p。
   - 有 ✕：一定要先處理，否則可能無法錄影。
3. **建議設定（2 小時以上的課程）：**

   | 設定 | 建議值 | 原因 |
   | --- | --- | --- |
   | 解析度 | 1080p，或「跟隨分頁」 | 投影片小字清楚 |
   | 幀率 | 30 fps；純投影片可用 15 fps | 15 fps 可大幅降低 CPU |
   | 影像編碼 | VP9；若課前檢查提示 CPU 負擔則用 VP8 | |
   | 影像位元率 | 4 Mbps（小字不清楚再調 6 Mbps） | 每小時約 1.9 GB |
   | 自動分段 | 60 分鐘 | 萬一當機，最多影響一段 |
   | 儲存位置 | 指定資料夾，或下載資料夾 | |

4. **麥克風（要錄自己的聲音才需要）。** 在設定頁按「授權並測試麥克風」，確認音量條會動；正常說話時音量條大約到一半到四分之三最理想，不夠就調高「麥克風音量」。**建議戴耳機。**
5. **試錄 1 分鐘。** 用任何有聲音的影片分頁試錄，停止後確認檔案能播放、有聲音。

## 二、課中

1. 進入 Meet 並把版面調好（例如釘選講者或投影片），**錄的是分頁畫面，版面就是錄出來的樣子**。
2. 在 Meet 分頁點 Tab Recorder 圖示 →「開始錄製此分頁」。
3. 確認三個標示：Meet 分頁標題前有 `● REC │`、工具列圖示有紅底 `REC`、右下角錄製視窗已自動最小化。
4. 錄製中可以切到別的分頁或縮小 Chrome，錄製不會中斷。**不要關閉錄製視窗**，也不要在 `chrome://extensions` 重新載入 Tab Recorder。
5. 想看狀態時點工具列圖示：popup 會顯示時間、已寫入大小、目前第幾段、以及實際 fps。
   - 若出現「電腦來不及編碼」警告，下課後回報，下次改用 VP8 或降低設定。
   - 投影片靜止時 fps 很低是正常的：分頁畫面沒有變化時，Chrome 本來就不送新畫面。

## 三、課後

1. 點工具列圖示 →「停止並存檔」，或直接關閉 Meet 分頁（會自動存檔）。
2. 等通知「錄製已存到…」出現（大檔案可能要幾秒到幾十秒）。
3. 用 VLC 或 Chrome 開啟檔案，抽查開頭、中段、結尾與分段接縫：
   - 時長正確、可拖曳進度條
   - 影音同步（看講者嘴型或投影片換頁的聲音）
   - 投影片小字可讀
4. 設定頁 →「最近的問題紀錄」→「複製診斷資訊」，連同下方回報表一起貼給我。

## 五、依回報決定下一步

- **一切正常：** 標記為 v1.0.0，定為日常使用版本。
- **CPU 過高或出現「來不及編碼」：** 先調整預設值（VP8、15 fps）；若仍不理想，進入第三階段，改用 WebCodecs 硬體 H.264 編碼並直接輸出 MP4。
- **其他問題：** 依診斷資訊與問題紀錄修正後，再錄一堂確認。
